# Pests and diseases library

The public `/crops/library/pests/` page defaults to the first valid crop in the signed-in user's registration selections, or Tomato for guests. Saved crops appear first in the selector. Explicit unknown crops/stages and crop–issue combinations return 404. Search, issue-type and stage filters are combined server-side; browsing needs no external service or JavaScript.

`data/pest_issues.json` contains editorial symptom summaries; `data/pest_crops.json` maps these to the 70 registration crops, crop-specific overrides and primary reference links. This is curated coverage, not an exhaustive inventory of every possible disease. The linked NIPHM, agricultural university and extension guides are the reference material, not live outbreak reports. `data/pest_research/guides.json` records the downloaded NIPHM reference hashes; copyrighted guide PDFs are not redistributed.

Growth stages are editorial scouting windows based on affected plant parts, not a predicted date of arrival. Root/tuber, cereal, flower and perennial stage labels adapt to crop type. Regional host records (notably the Florida lotus southern-blight report) are explicitly qualified in their entry. No pesticide doses or unsupported outbreak alerts are generated. Detailed reference prose is currently English; crop names retain existing translations.

Photographs live in `static/images/pests/`, with original source, author, licence, source-thumbnail URL and checksum in `credits.json`. Each detail page exposes this attribution. Every bundled photograph has an explicit `verified_crops` allowlist in `credits.json`. Selection first checks a crop–issue asset (`<crop-slug>--<issue-slug>`), then accepts a shared issue asset only if the selected crop is in its allowlist. Unknown hosts, other crops, laboratory cultures and unmatched species are withheld. Crop-labelled PlantVillage examples retain original bytes, dataset category, filename, attribution and licence links. Uploaded photographs remain scoped to their `PestEntry` crop. When no verified photograph exists for the selected crop and issue, the UI explicitly requests a verified crop photograph; an administrator can add it through that crop’s editor. When adding photographs, inspect both the depicted subject and source metadata; a Commons search match alone is insufficient. Do not use drawings, unrelated species or a screenshot of a paper as a disease photograph.

Run `python manage.py test crops.test_pests` for selection, filtering, source/asset integrity and invalid cross-crop navigation checks.

## Administrator portal

Open `/crops/library/pests/manage/` from **Admin dashboard → Manage pests & diseases**. Active staff or accounts with the existing administrator profile role can use the portal; farmers receive 403 and guests are sent to login. Select a crop and click a reference or saved card. **Add pest or disease** creates a new crop-specific card with a stable generated URL.

The editor saves symptoms, more information, treat-now guidance, organic control, chemical control, preventive measures, growth stages, title/type, optional reference URL and a photograph/caption to `PestEntry`. Saving publishes immediately and redirects to a blank new-entry form with the same crop selected. Text, stage selections and uploaded-file fields reset only after a valid save; invalid submissions retain their text and show validation errors. Existing reference cards are prefilled on their first edit. Changes apply only to that crop, and database content is read on every request so it appears without a server restart. Empty saved sections show “Details have not been added yet.” Uploaded photos replace the stock reference photo on both cards and detail pages; clearing an upload restores the reference photo where available.

Uploads are validated JPEG, PNG or WebP images up to 5 MB, with UUID filenames under `MEDIA_ROOT/pests/`. Keep `MEDIA_ROOT` persistent and serve `MEDIA_URL` through the production web server/storage; Django serves media locally in debug mode. Apply `python manage.py migrate` on other installations. `PestEntry` is also registered in Django admin. Run `python manage.py test crops.test_pest_admin` for permission, publishing, upload-validation, crop-isolation and escaping checks.
